# Changes relative to the stock Hugging Face Qwen3-VL forward

One line each; the code carries a short `# changed:` comment at each place. "Exact" = same math as stock (floating-point results can
differ in the last bits because kernels see different shapes); "approx." = an intended approximation of the method.

| # | where | change | why | exact? |
|---|---|---|---|---|
| 1 | `model.embed_patches` | ViT patch embedding Conv3d (kernel = stride = patch) computed as `F.linear` with the flattened kernel (`--linear-patch-embed`, "+pe") | MPS runs this Conv3d at ~0.02 TFLOP/s (~300x slower than the matmul) | exact |
| 2 | `model.grid` | ViT position-embedding interpolation, ViT 2-D RoPE, LLM mRoPE position ids and prompt token embeddings computed once per (resolution, prompt) and cached | identical for every frame of a stream | exact |
| 3 | `vit.run_vit` | ViT forward re-implemented layer by layer with the stock modules: only patches of kept blocks enter (S) | dropped blocks cost nothing | approx. (S) |
| 4 | `vit.run_vit` | one `scaled_dot_product_attention` call per layer over the single image instead of the `cu_seqlens` variable-length path | batch-1 stream; same attention | exact |
| 5 | `vit.run_vit` | T_vit: queries = patches of changed blocks only; keys/values = their fresh post-RoPE K/V + cached K/V of unchanged kept patches; the per-layer cache is updated every frame | unchanged blocks are not recomputed | approx. (T_vit) |
| 6 | `vit.run_vit` | merger and DeepStack-merger outputs cached per block; unchanged blocks take their cached outputs | same | approx. (T_vit) |
| 7 | `llm.llm_inputs` | dropped blocks removed from the LLM sequence; remaining tokens keep their full-grid mRoPE positions | S shortens the LLM too | approx. (S) |
| 8 | `llm.run_exact` | stock LLM forward continued from the previous frame's `DynamicCache` cropped to the first changed position P; only `[P, L)` is prefilled (DeepStack features sliced to the suffix) | causal LLM: the prefix is unchanged | exact |
| 9 | `llm.plan_llm` | if nothing changed at all, the previous embedding is returned without running the LLM | free | exact |
| 10 | `llm.run_approx` | T_llm: decoder layers re-implemented with the stock modules over a row subset R; fresh K/V written into a full-grid slot cache, attention over the cached K/V of all current positions with a causal mask by sequence index; DeepStack added only to visual rows in R; final norm on the last row only | recompute only what changed after P | approx. (T_llm) |
| 11 | `temporal.to_device` | all index sets (kept / recomputed blocks, LLM rows, slots) built on the host (numpy) and uploaded; MACs counted from the same host indices | in a long, memory-pressured MPS run an index tensor from on-device `nonzero()` once held garbage and corrupted the caches | exact |
| 12 | `model.merge_lora` / `model.attach_lora` | the retrieval LoRA is merged into the weights at load (`W += B @ A` in fp32, cast back) instead of a PEFT wrapper; `--no-lora-merge` instead wraps each target Linear as `base(x) + B(A(x))` with fp32 A, B and an fp32 sum (PEFT's computation, no `peft` dependency) | merged = same compute graph as the zero-shot model; unmerged for bf16, where the merge rounding drops much of the update | merged: exact up to one rounding of W (fine in fp16 / fp32, lossy in bf16) |
| 13 | `model.store_linear_weights_bf16` | CPU option: `nn.Linear` / large `nn.Embedding` weights stay bf16 and are upcast per call (patches their `forward` process-wide); everything else fp32 | halves resident memory on a 16 GB Mac (bf16 -> fp32 is exact) | exact |
| 14 | `qwen_embedder.py` | reference embedding wrapper trimmed to images + text (no video), no automatic move to CUDA; embedding = final hidden state of the last token (batch 1: no padding) | device-agnostic loading | exact |
| 15 | `spatial.lt_keep_mask` | if S would drop every block (a perfectly uniform screen), the top-left block is kept | the LLM needs at least one visual token | method detail |
| 16 | `vit.KERNELS`, `llm.KERNELS`, `cpu_compile.enable` | dense per-layer parts (ViT: norm1 -> qkv -> RoPE, proj + residual -> norm2 -> MLP; T_llm: norm -> q/k/v -> q/k norm -> mRoPE, o_proj + residual -> norm -> MLP) moved into kernel functions (same ops, same order); `--compile` swaps in `torch.compile(dynamic=True)` versions and compiles the HF LLM forward of the exact path; attention, K/V cache I/O and host planning stay eager | CPU: fuses the element-wise work around the matmuls | exact up to float reassociation (cos >= 0.99999) |
| 17 | `model.load_model` (`--weight-storage bf16-llm-fp32`) | as #13, then the LLM decoder-layer weights are upcast to fp32 once at load (ViT, input-embedding table stay bf16) | no per-call upcast in the LLM (~7 GB resident) | exact (bitwise = #13) |
| 18 | `spatial.gridkeep_keep_mask` (`--spatial lt-grid`) | Grid Keep: on top of the lt mask, the flat components of lt (blocks linked by its left / upper equalities) are cut into 2x2-block tiles and every (component, tile) group without a kept block keeps its top-left block; kept blocks then go through the same path as any kept block (own position, full mRoPE slot) | large flat areas keep a sparse grid of blocks instead of one | approx. (part of S) |
